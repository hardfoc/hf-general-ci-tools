🚀 hf-general-ci-tools

Reusable GitHub Actions workflows (ru-*.yml) for C/C++ linting and static analysis, host CMake builds, documentation (Doxygen + Jekyll to GitHub Pages), link and lint checks, and a single required CI gate. The repositories in the hardfoc organisation call them; ESP-IDF firmware builds live in the sibling hf-espidf-ci-tools.

Each workflow is self-contained. It calls only third-party actions, which are pinned to commit SHAs, and never another workflow of this repository at a moving ref. Pinning a caller to @v1 therefore pins everything it runs.

Versioning

Pin the moving major tag:

1

uses: hardfoc/hf-general-ci-tools/.github/workflows/<workflow>.yml@v1

Releases are semver tags (v1.0.0, v1.1.0, …). v1 always points at the newest v1.x.y, so callers get fixes and new optional inputs, never breaking changes. A removed input, a new required input or a new required permission only arrives with a new major (@v2). Pull requests here are checked for exactly those changes. See docs/VERSIONING.md and CHANGELOG.md.

After a fix lands here, start a new run. “Re-run failed jobs” reuses the reusable-workflow revision that the original run resolved.

Permissions contract

Each workflow declares minimal permissions on every job. A called workflow cannot ask for more than its caller grants. If it does, the run fails before any job starts (startup_failure). Grant at least the following, on the calling job or at the top of the calling workflow. The self-CI fails if a workflow’s job permissions ever differ from this table.

| Workflow | Caller must grant | Why | | — | — | — | | ru-ci-gate.yml | contents: read | read the calling workflow to verify needs | | ru-cpp-analysis.yml | contents: read | checkout | | ru-cpp-lint.yml | contents: read, pull-requests: write | checkout; cpp-linter thread comments and annotations | | ru-docs-linkcheck.yml | contents: read | checkout | | ru-docs-publish.yml | contents: write | push to the deployment branch; required on pull requests too, although PRs never deploy | | ru-host-ci.yml | contents: read | checkout | | ru-markdown-lint.yml | contents: read | checkout | | ru-release.yml | contents: write | create the GitHub Release | | ru-yaml-lint.yml | contents: read | checkout |

One required check: the CI gate

Put every job of a repository’s CI in one workflow, and end it with the gate:

10

  ci-gate:
    name: CI gate
    needs: [build, lint, docs]     # every other job in the workflow
    if: always()                   # a skipped required check counts as passing
    uses: hardfoc/hf-general-ci-tools/.github/workflows/ru-ci-gate.yml@v1
    permissions:
      contents: read
    with:
      needs_json: $
      allow_skipped: docs          # jobs that may be skipped by design

The repository ruleset then requires only the check CI gate / gate. GitHub names checks from a called workflow <calling job> / <called job>. The gate fails if any needed job failed or was cancelled, or was skipped without being listed in allow_skipped. It also fails if the calling workflow leaves a job out of needs or drops if: always().

Workflows: callers and inputs

Each example is the smallest working caller. The inputs tables are generated from the workflow files (.github/scripts/gen_readme_inputs.py), and CI fails if they go stale.

How this repository tests itself

Workflow What it checks
ci-self.yml Runs actionlint with shellcheck (pinned, any finding fails). Fails any run: block ending in a bare cond && cmd. Checks the permissions contract against the table above, the README inputs tables, and breaking changes against the PR base. Runs unit tests for these checks, and runs the CI gate on itself
ci-docs-publish.yml Builds this site (Jekyll source .) and a fixture site whose source is a subdirectory
ci-host-ci.yml Runs ru-host-ci on a fixture: preset path on clean code must pass; -S/-B path with seeded defects must report findings
ci-cpp-lint.yml, ci-cpp-analysis.yml, ci-docs-linkcheck.yml, ci-markdown-lint.yml, ci-yaml-lint.yml Each runs its workflow on this repository

Third-party actions are pinned to commit SHAs with a # vX.Y.Z comment, and Dependabot keeps them current. Contributions follow CONTRIBUTING.md. Licensed under GPL v3.
